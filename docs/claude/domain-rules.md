# Domain rules

- **Event status flow**: WAITING → ACTIVE → COMPLETED (unidirectional). Never revert status in code.
- **Hoofdstukken** (openspec/changes/chapters): a draaiboek (template or production callsheet) is an ordered list of hoofdstukken, each with its items; **every item is in exactly one hoofdstuk** (`chapterId` is required) and a linked item sits in its parent's. A hoofdstuk has no duration or anchor: its start, end and duration follow from its items (`services/productionTiming.ts`), and the livestream ends with the last item (`liveEnds`, null without timed items). The order is written as a whole (`PUT …/structure`, `flattenChapters` makes the flat `orderIndex`), never edited per row. Production hoofdstukken (`ProductionChapter`, table `ProductionSegment`) are `{id, productionId, name, orderIndex}`; their bezetting (`ChapterRoleAssignment`) keeps the routes `/api/production/segments/:segmentId/...`. Standard positions live on the template hoofdstuk. Segment templates, standard positions per segment name and the segment duration/anchor are gone (migration `20261101100000_chapters_release_2`). Older backups/exports with `segments` are converted on restore (`ChapterRestore`, `services/chapterMigration.ts`).
- **Time anchoring**: a draaiboek has at most one `isTimeAnchor` item per `anchorType` (`LIVESTREAM_START`, `MATCH_START`; never a hoofdstuk). Every anchor starts at its own time (live time, kickoff); the items after it follow until the next anchor, the items before the first anchor go backwards. One rule computes it, `services/laneTimes.ts` (through `layOutTimes` in `services/draaiboekFile.ts`): Tijden herberekenen, Draaiboek toepassen, the draaiboek import, the template GET (`startOffsetSec`), `/timing` and `liveEnds`; the kit never computes draaiboek times itself. **Lanes** (openspec/changes/parallel-lanes): an item with only Zaal runs in the hall lane, only Stream in the stream lane; both/neither, an anchor and the start of a hoofdstuk are samenkomstpunten. Between two samenkomstpunten both lanes start together; the next one starts when the longest lane ends. A hoofdstuk's optional **Minimale duur** (`minDurationSec`) makes the next hoofdstuk start no earlier than its start + minimum. Without lanes or minimums items follow end to end. During the show `relayOutFrom` replans from the active item with the same rule.
- **A moved match moves its production**: the calculated times are stored as absolute instants (`Production.liveTime` / `setupTime` / `crewCallTime`, `CallSheetItem.timeStart/timeEnd`, `ProductionEvent.plannedStartTime/plannedEndTime`), so when a match date changes (manual match PUT, match import upsert) `shiftProductionTimesForMatchDateChange` (`services/matchChange.ts`) shifts them by the exact UTC delta, in the same transaction. `actualStartTime` stays; a production that is live right now is left alone (warning in the log). Anything else that changes `MatchSchedule.date` must call it too.
- **Beschikbaarheid**: `GET /api/production/:id/attendance` gives every person (no paging) with group and presence, plus the minimum staffing. Entertainment = every skill belongs only to ENTERTAINMENT positions (`domain/crewGroup.ts`); everyone else, also without skills, is Crew. The minimum staffing rule, counts and skill codes live in `domain/minimumStaffing.ts` (`MINIMUM_STAFFING_ROLES`); one person fills one role (bipartite matching, required roles first).
- **Day planning (opbouw / verzamelen)**: `Production.setupTime` / `crewCallTime` are null unless a production deviates; `services/dayPlanning.ts` (`planDay`, `plannedTimesOf`) fills in the organization's defaults (`dayPlanning` setting: `crewCallMinutes` 30 before live, `setupMinutes` 150 before the day's first stream; edited via `/api/settings/club-config`). Opbouw only counts for the first stream of the Amsterdam day. Never compute "30 minutes before live" yourself: use `planned` (GET `/api/production/:id` and `/active`) or the `planning` of `/api/reports/daily-occupancy`.
- **Role reports**: `/api/reports/entertainment-roles` (ENTERTAINMENT positions) and `/api/reports/crew-roles` (TECHNICAL + GENERAL) give a column per position of the organization (by `sortOrder`) and per production the names, from the production-wide positions and the segment assignments together. No skill codes hard-coded.
- **Settings persistence**: settings are per organization (`OrganizationSetting`: vMix URL/instances, callsheet push, sponsor filter types, scoreboard/shot clock URL, production team names, `sponsorCarouselExtra`); only installation-wide keys (`GLOBAL_SETTING_KEYS` in `services/appSettings.ts`: `activeSeasonId`) stay in `Setting`. Always go through `getSetting`/`setSetting` (cache keyed by organization + key; "not set" is cached too, so never write settings rows any other way). The **own club** is not a setting: it is `Organization.clubId` (`services/ownClub.ts`), shown as `ownClubId` by `/api/settings/club-config` and as the club in Beheer → Organisaties. A settings restore into one organization skips installation-wide keys (`activeSeasonId`, `activeSeasonName`). Accessed via `/api/settings` for the chosen organization.
- **Seasons**: `MatchSchedule` and `Player` have a required `seasonId`. A match's season is always derived from its date (1 July–30 June, Europe/Amsterdam) via `services/season.ts` — never set it by hand. Season-bound list endpoints default to the active season (`activeSeasonId` setting) with an optional `?seasonId=` override; production-bound lookups use the production's match season. Clubs are global. KNKV downloads go to `storage/seasons/<YYYY-YYYY>/`.
- **Times**: stored/sent as UTC; shown and entered as Europe/Amsterdam via `lib/time.ts` (kit) / `utils/time.ts` (API); text for vMix and reports is formatted in Europe/Amsterdam on the server; never format with the server/browser zone (no `getHours`/`setHours`, `toLocale*String` without `timeZone`, `iso.substring(0, 16)` or `new Date('2026-11-14T19:30')`). A time without zone from outside means Amsterdam time (`parseInstant`; invalid → 400). DST: a repeated October hour takes the first (summer-time) occurrence, a skipped March hour moves forward. The API and kit tests run with `TZ=UTC` (set in their vitest/vite config; override with e.g. `TZ=America/New_York`), the e2e API with `TZ=UTC` and the browser via `timezoneId`. Relative durations/countdowns are zone-free and stay as they are.
- **User manual (handleiding)**: Markdown in `apps/korfbal-stream-kit/src/handleiding/live/` (crew, LIVE) and `.../beheer/` (Beheer), bundled into the app (works offline) and shown at `/handleiding` and `/admin/handleiding`. File names `NN-slug.md` give order and slug; the `?` button opens the chapter for the current screen via `handleiding/helpTopics.ts`. Written in Dutch for end users, with the exact UI labels. When you change a screen's behaviour or labels, update its chapter in the same change.
- **Positions by name**: never look up or create a position by its exact name. Use `findPositionByName` (`domain/positionSkill.ts`, ignores case/spacing and knows aliases like `regie` → "Regie livestream") or `findOrCreatePosition`/`findExistingPosition` (`services/positions.ts`). Exact lookups created duplicates ("regie" next to "Regie livestream", "Showcaller" next to "Show caller"); migration `20261014170000_merge_duplicate_positions` merged them. The seed matches the same way and renames an existing skill code (e.g. `SHOW_CALLER` → `SHOWCALLER`) instead of adding one.
- **Seeded RNG**: Sponsor row/slide generation uses `mulberry32` seeded by a `seed` query param for reproducible randomization.
- **Vitest test files**: DB integration guard is inside the spec file via `REQUIRE_DB` env check — not a separate file suffix.
